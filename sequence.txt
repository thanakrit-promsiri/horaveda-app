โครงสร้างโปรเจกต์ horaveda-app นี้ถูกจัดระเบียบตามมาตรฐาน Clean Architecture ในภาษา Go โดยแบ่งหน้าที่การทำงานของแต่ละส่วนดังนี้ครับ:LICENSE: ไฟล์ระบุเงื่อนไขและลิขสิทธิ์การใช้งานโปรเจกต์build.sh / run.sh / test.sh: สคริปต์สำหรับช่วยในการ Build, รันเซิร์ฟเวอร์ และรันการทดสอบระบบอัตโนมัติcmd/server/main.go: จุดเริ่มต้นหลักของแอปพลิเคชัน (Entry point) ทำหน้าที่โหลดคอนฟิก, เชื่อมโยง Dependency Injection และเริ่มรัน HTTP Server   coverage.html / coverage.out: ไฟล์รายงานผลและสถิติความครอบคลุมของการทดสอบโค้ด (Test Coverage)go.mod / go.sum: จัดการแพ็กเกจและ Dependencies ภายนอกของภาษา Gohoraveda.postman_collection.json: ชุดคำขอสำหรับทดสอบ API ผ่านโปรแกรม Postmaninternal/config/config.go: จัดการโหลดค่าคอนฟิกและตัวแปรแวดล้อมต่างๆ ของระบบinternal/delivery/http/: ชั้นติดต่อสื่อสารผ่าน HTTP Protocolhandler/: จัดการรับ Request และส่ง Response กลับหาผู้ใช้งาน (ประกอบด้วย auth_handler.go, debug.go, logout.go, register.go, และ verify.go)   middleware/auth_middleware.go: ตัวกรองคำขอเพื่อตรวจสอบสิทธิ์ความปลอดภัย (Authentication/Token Validation) ก่อนเข้าถึง Handler   router.go: ลงทะเบียนเส้นทาง (Routes) ทั้งหมดของ API พร้อมระบบบันทึก Log คำขอ   internal/domain/model.go: โครงสร้างข้อมูลกลาง (Data Models และ Structs) ที่ใช้ร่วมกันทั้งแอปพลิเคชัน   internal/repository/auth_repository.go: ชั้นติดต่อฐานข้อมูล (Database/Supabase) สำหรับดึงและบันทึกข้อมูลที่เกี่ยวข้องกับการยืนยันตัวตน   internal/service/auth_service.go: ชั้นประมวลผลธุรกิจ (Business Logic) เช่น การจัดการระบบสมาชิกและการตรวจสอบรหัสซีเรียลlogs/app.log: ไดเรกทอรีสำหรับเก็บไฟล์บันทึกการทำงานของระบบ (Log files)migrations/: โฟลเดอร์สำหรับจัดการโครงสร้างและชุดคำสั่งอัปเดตฐานข้อมูล (Database Migrations)pkg/: แพ็กเกจกลางที่สามารถนำไปใช้ซ้ำได้ทั่วโปรเจกต์logger/logger.go: ตั้งค่าและสร้างเครื่องมือบันทึก Log ส่วนกลางด้วย Zap และระบบหมุนเวียนไฟล์ Log (Rotation)response/: เครื่องมือมาตรฐานสำหรับจัดรูปแบบการส่งข้อมูล Response และจัดการข้อผิดพลาด (Errors)   req/req.txt: บันทึกรายการคำขอหรือข้อมูลตัวอย่างประกอบการพัฒนาsequence.txt: แผนผังลำดับการทำงาน (Sequence Diagram) sequenceDiagram
    autonumber
    actor User as ผู้ใช้งาน
    participant Nginx as Nginx Reverse Proxy
    participant Web as ssr-web (Frontend)
    participant API as horaveda-app (Backend)
    participant DB as Supabase (PostgreSQL)
    participant Lahiri as lahiri-api
    participant GoSwisseph as go-swisseph (Go Wrapper)
    participant CSwisseph as swisseph (C/C++ Core & Ephe Files)
    participant LLM as One API / LLM
    
    User->>Nginx: ขอเข้าใช้งานเว็บ / ส่งฟอร์มผูกดวง
    Nginx->>Web: โหลดหน้าเว็บ (SSR)
    
    Note over User,Web: ผู้ใช้งาน Login สำเร็จ -> Backend เซ็ต Token ลง Cookie
    
    Web->>Nginx: ส่ง HTTP Request (แนบ Cookie / Token มาด้วยอัตโนมัติ)
    Nginx->>API: ส่งต่อ Request พร้อม Cookie ไปยัง Backend (horaveda-app)
    
    %% Go Backend ดึง Token จาก Cookie มาเช็กสิทธิ์
    API->>API: ดึงและตรวจสอบ Token จาก Cookie
    API->>DB: ตรวจสอบข้อมูลผู้ใช้ / สถานะ Login ใน Supabase (ถ้าจำเป็น)
    DB-->>API: ยืนยันตัวตนผู้ใช้สำเร็จ
    
    %% ขั้นตอนการคำนวณทางดาราศาสตร์เชิงลึก
    API->>Lahiri: ส่งคำขอคำนวณตำแหน่งดวงดาว (ระบบนิรายนะ)
    Lahiri->>GoSwisseph: เรียกฟังก์ชันคำนวณองศาดวงดาว / Ayanamsa (Lahiri)
    GoSwisseph->>CSwisseph: CGO / เรียกใช้งานฟังก์ชัน C/C++ (Swiss Ephemeris)
    
    Note over CSwisseph: ดึงไฟล์ ephe (ep4, sat) มาคำนวณทางคณิตศาสตร์ดาราศาสตร์ขั้นสูง
    
    CSwisseph-->>GoSwisseph: ส่งคืนค่าพิกัดดวงดาวดิบ (Raw Ephemeris)
    GoSwisseph-->>Lahiri: ส่งคืนค่าองศาดาวที่ปรับเทียบแล้ว
    Lahiri-->>API: ส่งคืนผลลัพธ์ตำแหน่งดาวและลัคนาที่สมบูรณ์
    
    %% ขั้นตอนแปลผลและบันทึก
    API->>LLM: ส่งข้อมูลดาว + Prompt ไปยัง One API
    LLM-->>API: ส่งคืนคำพยากรณ์จาก AI
    
    API->>DB: บันทึกข้อมูลการผูกดวง / ผลพยากรณ์เชื่อมโยงกับ User ลง Supabase
    DB-->>API: บันทึกสำเร็จ
    
    API-->>Nginx: ส่งข้อมูลผลลัพธ์ทั้งหมดกลับ (JSON)
    Nginx-->>Web: ส่งข้อมูลกลับ
    Web-->>User: แสดงผลหน้าจอผูกดวง + คำพยากรณ์
